# Burbank Stingrays Swim Team Website

A modern, responsive website redesign for the **Burbank Stingrays Swim Team**.

This project is intended to create a cleaner, easier-to-navigate, mobile-friendly public website for swimmers, parents, coaches, prospective families, and members of the Burbank Stingrays community.

The website is being developed independently as a modern frontend project using **HTML, CSS, and JavaScript**, with the goal of being hosted publicly using **GitHub Pages** while also being easy to run locally on a laptop or desktop computer.

---

# Project Overview

The existing Burbank Stingrays website provides important team information, but this project explores a redesigned experience focused on:

* Simple navigation
* Mobile-first design
* Faster access to schedules and meet information
* Clear information for prospective families
* Team announcements
* Coach information
* Safe Sport resources
* Parent and swimmer resources
* Team history and achievements
* A unique interactive team photo collage
* Improved accessibility
* Consistent Stingrays branding

The goal is not simply to create a visually different website.

The goal is to create a website that makes information easier to find and provides a stronger online identity for the Burbank Stingrays.

---

# Project Goals

The primary goals of the website are:

1. Create a clean and modern public-facing team website.
2. Make the website easy to use on phones, tablets, laptops, and desktop computers.
3. Reduce the number of steps required to find important information.
4. Give current families quick access to schedules, meets, announcements, and resources.
5. Give prospective families a clear path for learning about and joining the team.
6. Preserve and display the history of the Stingrays through photos and team memories.
7. Keep sensitive or administrative information outside of the public website.
8. Maintain compatibility with existing services such as GoMotion/SportsEngine where necessary.
9. Create a maintainable website that can grow over time.
10. Use the project as a practical implementation of modern frontend web-development techniques.

# Photo Submissions

A future version of the website may allow approved members of the Stingrays community to submit team photographs.

Submitted photographs should **not automatically appear publicly**.

The planned workflow is:

```text

            ↓
      Approval Queue
            ↓

            ↓

            ↓

```

This moderation process is particularly important because the organization includes youth athletes.

# Lucide Icons

The website uses **Lucide** for interface icons.

Lucide provides lightweight SVG icons that remain sharp at different screen sizes.

Examples include:

```html
<i data-lucide="home"></i>
<i data-lucide="clock"></i>
<i data-lucide="calendar-days"></i>
<i data-lucide="users"></i>
<i data-lucide="trophy"></i>
<i data-lucide="camera"></i>
<i data-lucide="upload"></i>
<i data-lucide="file-text"></i>
<i data-lucide="shield-check"></i>
<i data-lucide="map-pin"></i>
<i data-lucide="mail"></i>
<i data-lucide="menu"></i>
```

Lucide can initially be loaded using its CDN.

Example:

```html
<script src="https://unpkg.com/lucide@latest"></script>
<script src="js/main.js"></script>
```

Inside `main.js`:

```javascript
lucide.createIcons();
```

Before production deployment, the Lucide dependency should be pinned to a specific stable version instead of relying permanently on `@latest`.

# Local Development

The website can be run directly on a laptop or desktop computer.

## Option 1 — Visual Studio Code Live Server

If using Visual Studio Code:

1. Open the project folder in VS Code.
2. Install the **Live Server** extension.
3. Open `index.html`.
4. Right-click the file.
5. Select:

```text
Open with Live Server
```

A browser should automatically open the website.

The local address may look similar to:

```text
http://127.0.0.1:5500/
```

or:

```text
http://localhost:5500/
```

---

# Local Development Using Python

If Python is installed, the project can also be served without installing another application.

Open a terminal inside the project directory.

Run:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000
```

To stop the server, press:

```text
Ctrl + C
```

---

# Testing on a Phone

The local development website may also be tested from a phone connected to the same network as the development computer.

Instead of using:

```text
localhost:8000
```

the computer's local network address can be used.

Example:

```text
http://192.168.1.25:8000
```

The exact IP address will depend on the local network.

Firewall settings may need to allow the connection.

This provides a useful way to test the site's mobile layout before publishing changes.

# GitHub Pages Limitations

GitHub Pages is excellent for hosting:

* HTML
* CSS
* JavaScript
* Images
* Static documents
* Public information

GitHub Pages does **not** provide a traditional backend server.

Therefore, functionality such as:

* User accounts
* Private databases
* Payment processing
* Secure administrator authentication
* Direct file uploads
* Private swimmer records

should not be implemented directly through GitHub Pages alone.

Additional services would be required.

Accessibility should remain an important part of the design.

Planned considerations include:

* Semantic HTML
* Proper heading structure
* Alternative text for meaningful images
* Keyboard navigation
* Visible focus indicators
* Sufficient color contrast
* Clear link text
* Large enough buttons
* Accessible forms
* Descriptive labels
* Reduced reliance on color alone

# Performance

The website should remain fast even as more team content is added.

Performance strategies may include:

* Compressing images
* Using modern image formats
* Lazy loading photographs
* Avoiding unnecessary JavaScript
* Minimizing large external libraries
* Using SVG icons
* Loading only required content
* Optimizing mobile images

# Gallery Performance

The full Team Memories archive should not load every photograph immediately.

Instead, future versions may use:

```text
Initial Photos
      ↓
User Scrolls
      ↓
Additional Photos Load
      ↓
User Continues
      ↓
Additional Photos Load
```

This technique reduces initial page-loading time and is particularly important for mobile visitors.
